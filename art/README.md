# Art pipeline

Sprites are generated as sheets by the Codex CLI image tool, then turned into true pixel art by `scripts/art/process.mjs`.

```
art/raw/            raw Codex output (sheets, one PNG per call image) + log-<call>.txt
art/queue/          one prompt file per Codex call (built by scripts/art/queue.mjs)
art/prompts.md      every prompt that was actually sent
art/sheets.json     spec: raw file -> kind -> ordered output keys (left to right)
art/anchors.json    anchors written by process.mjs (read by manifest.mjs)
art/preview/        contact sheets from preview.mjs
public/assets/      game-ready sprites: skins/ heads/ hats/ sceneries/ icons/
src/ui/art/manifest.ts   GENERATED by manifest.mjs, never edit by hand
```

## Everyday commands

```bash
node scripts/art/queue.mjs        # (re)build art/queue/*.txt and art/sheets.json
bash art/run-queue.sh             # run missing Codex calls, one at a time; stops on a usage limit
npm run art:process               # all sheets in art/sheets.json whose raw file exists
node scripts/art/process.mjs heads-1.png   # only that raw file
npm run art:manifest              # rewrite src/ui/art/manifest.ts from public/assets
node scripts/art/preview.mjs      # art/preview/<professor>.png, overview.png, sceneries.png
```

Always run `art:process` then `art:manifest` (the manifest only lists PNGs that exist, so a missing sprite
simply falls back to the procedural drawing).

## Adding or replacing a sprite

### A. A pixel head from a real photo of a professor (the owner's flow)

1. Make a pixel-art head of the professor: front view, no neck, no body, about 56 px tall (45-60 px wide),
   dark 1px outline, hard edges, transparent background. A square pixel grid with no anti-aliasing.
2. Save it as `public/assets/heads/<professorId>.png` (ids: `edecio gladimir b2 wagner guto b1 angelo pablo`).
   Overwriting the generated head is fine.
3. Add its anchor (the bottom-centre of the chin, in pixels from the top-left) to `art/anchors.json`:
   `"heads/<professorId>": { "x": <centre column>, "y": <last row of the chin> }`.
   If you leave this out the manifest has no anchor and the UI should fall back to bottom-centre, so
   prefer adding it. Chin = lowest point of the face (the tip of a beard counts); long hair that falls past
   the chin must not move the anchor.
4. `npm run art:manifest`, then `node scripts/art/preview.mjs` to check the head on every skin.

Alternatively drop the pixel head into `art/raw/` as a one-item sheet, add
`{ "file": "real-edecio.png", "kind": "head", "keys": ["edecio"] }` to `art/sheets.json` and run
`node scripts/art/process.mjs real-edecio.png`: the script cleans the background, snaps it to the pixel grid,
rescales to the target height and computes the anchor for you. (`queue.mjs` keeps hand-added entries.)

### B. Generate a new sheet with Codex

1. Put the prompt in `art/queue/NN-label.txt` (or add data to `scripts/art/queue.mjs` and re-run it).
   Rules that work: 4 items per sheet in one row, flat magenta background, "HEADLESS bodies ending in a neck
   stub" for skins, "heads only, no neck" for heads, one item per image for sceneries, keep the 16-bit style words.
2. `bash art/run-queue.sh` (never in parallel).
3. Register the sheet in `art/sheets.json` (queue.mjs does it for the planned sprites), then
   `node scripts/art/process.mjs <raw file>.png` and `npm run art:manifest`.

## How process.mjs works

- Background: if the border is transparent, alpha is hardened; otherwise the border colour (median) is flood
  filled with tolerance 70 (so magenta-ish pixels inside a sprite survive), enclosed pockets of the same colour are
  removed, and magenta-tinted fringe pixels touching the background are eroded (dark ones are recoloured to the outline
  colour instead of deleted, so outlines stay closed).
- Items: connected components (8-neighbour); the N largest are the items (N = number of keys), smaller pieces
  are merged into the nearest item, specks are dropped, items are ordered left to right. A wrong count, touching
  items or absurd areas abort that sheet with an error.
- Block size (the "fake pixel" size of the generation): the edge profile of the columns/rows is scanned with a comb
  of period p (4..16 px, fractional, limited to 0.6-1.4x of the size expected for the target); the smallest p scoring
  within 3% of the best wins. x and y must agree within 12%. The native size must land within +-12% of the target
  (skins 48 px tall, heads 56 px tall, icons 20 px tall, hats 52 px wide), otherwise the item is resampled straight to
  the target size.
- Resampling: one output pixel per block, colour = the most common (16-level quantised) colour in the block's
  central 50%, alpha is 0/255 (block must be at least half covered). Then fringe/isolated-pixel cleanup and trim.
- Anchors (pixels from the top-left of the trimmed sprite):
  - skin: the neck stub top = topmost row (top 35%) that has a run of 3+ skin-coloured pixels, centre of that run; `y`
    is that row + 1 so the chin overlaps the first neck row. Fallback: centre of the top opaque row.
  - head: x = middle of the sprite, y = lowest opaque pixel in the central column band (chin or beard tip).
  - hat: bottom-centre.
  - To compose: draw the head at `skin.anchor - head.anchor`; the hat at `headTopLeft + (head.w/2, ~4) - hat.anchor`.
- Sceneries: centre-cropped to 16:9 and block-sampled down to 480x270 (no background removal).
