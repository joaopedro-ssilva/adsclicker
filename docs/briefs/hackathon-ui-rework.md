# Hackathon UI rework (full screen)

The owner played the first version and found the interface poor: the mode was squeezed into the classroom layout (stage on the left, a narrow side panel on the right). He sent six sketches generated by another model. This rework moves the mode to a **full-screen layout** guided by those sketches.

## What the owner asked

> "não é pra seguir à risca, é pra priorizar o system design atual e as informações atuais, esses esboços são para guiar apenas, mas ficaram bem bons"

So:

- The sketches set the **layout and hierarchy** of each screen. They are not pixel targets, and their invented details (blue buttons, different stage names, three stages, a carousel) do not override the game.
- The **current design system wins**: `src/ui/styles/tokens.css`, the kit in `src/ui/kit` (Button, IconButton, Badge, RarityBadge, ProgressBar, Meter, Modal, Tooltip, Icon...), the two fonts (`--font-display` pixel font for short labels and numbers, `--font-text` for reading text), the accent colour, hard 2px borders and offset shadows. No blur, no rounded corners, no gradients on panels.
- **Every piece of information and every action that exists today stays reachable.** A sketch that omits something (the daily Hackathon, the automatic toggle, drops, set bonuses, respec, reroll, bulk recycle, totals...) does not remove it. Find it a place.

## The shell (already built, frozen)

`src/ui/hackathon/screen/`:

- `HackathonScreen.tsx` picks the view: fight, rewards, hub, a window, or a notice. `GameApp` renders it full screen (`.game[data-mode='hackathon']`); there is no side panel in this mode.
- `TopBar.tsx`: logo, a centre slot (the tabs while browsing), resources (level with XP line, ADScoins, Commits, Café), back to the classroom, sound, settings.
- `TabNav.tsx`: Aluno, Itens, Habilidades, Mentores, Fases. In the top bar on wide screens, a bottom bar under 1180px.
- `uiStore.ts` (`useHackathonUi`): `tab`, `setTab`, `focusItem`, `openItem(id)` (opens the items tab on that item), `auto`, `setAuto` (the automatic-mode preference shared by every start button).
- `Window.tsx`: the framed window every non-hub screen uses (`title`, `icon`, `subtitle`, `aside`, `size` md 880 / lg 1040 / xl 1240). Its body scrolls.
- `Card.tsx`: a small framed card over the arena (`title`, `icon`, `aside`).
- `screen.css`: the frames and the variables `--hx-line` (frame line), `--hx-glass` (panel background), `--hx-glass-raised`, `--hx-gap`.

Screen entry points the shell imports (currently thin placeholders that wrap the old tabs, replace their insides):

- `src/ui/hackathon/hub/HubView.tsx` → `HubView({ profile })`
- `src/ui/hackathon/panel/fases/StagesWindow.tsx` → `StagesWindow({ profile })`
- `src/ui/hackathon/panel/itens/ItemsWindow.tsx` → `ItemsWindow({ profile })`
- `src/ui/hackathon/panel/habilidades/SkillsWindow.tsx` → `SkillsWindow({ profile })`
- `src/ui/hackathon/panel/mentores/MentorsWindow.tsx` → `MentorsWindow({ profile })`

Keep those names and props.

## Rules for everyone

- **Stay in your folders** (listed in your task). Everything else is read-only: the shell, the store (`src/ui/hackathon/store`), `src/hackathon/**`, `src/shared/**`, `src/server/**`, the kit, the classroom UI. If you need something from a frozen file, work around it and say so in your report.
- Other engineers are editing other folders of the same working tree at the same time. Type or lint errors outside your folders are theirs: ignore them, and re-run later. If the dev server shows an error from a file that is not yours, wait a minute and retry.
- **No git state changes**: no commit, stash, checkout, reset or branch. The lead commits.
- The owner's dev server runs on `http://localhost:3000` and follows the working tree. Do not start another one, do not stop it. If styles look stale after a CSS change, append a blank comment line to `src/app/globals.css`, save, then remove it.
- Do not touch Docker containers or the database. Never print or copy anything from `.env.local`.
- No new dependencies.
- Code and comments in English, interface text in Brazilian Portuguese (sentence case, no exclamation overload). One component per file, small files, same comment style and density as the files around. Class prefixes: `hk-` for the windows and the hub, `ar-` for the fight and rewards, `hx-` is the shell's (do not add `hx-` rules).
- Remove what you replace: dead components and dead CSS in your folders go away. CSS that was written for the 440px side panel (`.hk-panel ...`, `.side-panel ...` assumptions) should not survive in your screens. `panel/hk-panel.css` only imports each folder's file; `panel/lib/**` is shared: add to it only if you own the need, never break another screen's use of it.
- Keep the existing `data-qa` attributes on the elements that still exist (tests and scripts use them).
- Responsive, with container queries on the `stage` container (`@container stage (max-width: 1179px)` and `(max-width: 719px)`), not media queries: desktop 1440×900 is the main target, 390×844 must work with no horizontal scroll (on phones the body scrolls and windows fill the width).
- Accessibility basics: real buttons, labels, focus visible, `prefers-reduced-motion` respected (see how the arena does it).
