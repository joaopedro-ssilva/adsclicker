# Loose ends and quality of life

The owner wants to add new features to ADSClicker, but first "conectar as pontas soltas": quality of life and achievements for things the game already does. The game is live (`main` deploys to production), so everything must be additive and keep existing saves loading.

## Common rules for every engineer on this pass

- Repo: `C:\Users\joaopedro\Documents\Workspace - 2026\Edécio-Clicker-Remastered` (Git Bash: `/c/Users/joaopedro/Documents/Workspace - 2026/Edécio-Clicker-Remastered`), branch `hackathon`. On this Windows machine shell heredocs with apostrophes or accents break: create and edit files with the Write and Edit tools. In Git Bash, prefix commands that pass a `/` argument to node with `MSYS_NO_PATHCONV=1`.
- Read `AGENTS.md` and `docs/ARCHITECTURE.md` first. `content` ← `engine` ← `store` ← `ui`. The engine is pure (no React, DOM, clock or random). Content is data. A new saved field needs a default and a tolerant reader in `engine/save.ts`, with a test that an old save loads. Interface-only preferences that do not affect the game (which section is open, a filter) live in small localStorage-backed stores in the UI, like `src/ui/game/panel/formatura/sectionsStore.ts`, not in the save.
- Interface text in Brazilian Portuguese, light humour about the subject and never about the person. Code and comments in English, in the style and density of the surrounding files. Use the kit (`src/ui/kit`) and the tokens; every theme, including the light ones, must stay readable.
- Three engineers work in the same tree at once, each with its own folders (listed in your task). Shared files (`engine/state.ts`, `init.ts`, `save.ts`, `content/types.ts`, the store, `content.test.ts`, `docs/GAME_DESIGN.md`): re-read right before each edit, make small additive edits, never rewrite whole. A type or test error coming from someone else's files: say so and move on.
- Do not touch `src/hackathon/**`, `src/ui/hackathon/**`, `src/server/**` (unless your task says so), `scripts/art/**`, `art/**`, `public/assets/**`. No new art is available: the image budget is spent, so nothing in this pass may depend on a new sprite.
- No git state changes (no commit, stash, checkout, reset). The lead commits and deploys. The owner's dev server runs on http://localhost:3000 and follows the working tree: do not stop it and do not start another one; if it is down, finish what you can verify without a browser and say exactly what was not seen. Never open or print `.env.local`. No new dependencies.
- Screenshots: `MSYS_NO_PATHCONV=1 node scripts/qa/screenshot.mjs / art/preview/<name>.png [--mobile] [--save=<raw-json-file>] [--wait=ms] [--clicks=N]` (run `npm run dev:save`, then decode `dev-save.txt` from base64 into a raw JSON file for `--save`), or a throwaway Playwright script next to `scripts/qa/` deleted after. Look at them with the Read tool. The API rate-limits repeated reloads (429 on sync is that limiter).
- Done means: `npx tsc --noEmit` clean (run `npx next typegen` first if route types look stale), `npx eslint src scripts` clean for your files, `npx vitest run` passing, and your feature seen in the browser at 1440x900 and 390x844.
- Report in English, brief and precise, for the lead engineer: what you built and where, what you verified in the browser and what you did not, deviations, and open questions for the owner.
